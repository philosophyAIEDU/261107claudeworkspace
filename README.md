# 🦉 필로소피 Claude 작업실

Claude Code(클로드 코드)를 위한 **한국어 작업실** 데스크톱 앱이에요.

## 1. 이 앱으로 할 수 있는 일

- **"예전에 어느 폴더에서 작업했더라?"를 끝내요.** 작업 폴더와 Claude와 나눈 대화(세션)를 모두 기억해 두었다가, 처음 화면에서 골라 **[▶ 이어서 작업하기]** 한 번으로 돌아가요.
- 화면은 익숙한 IDE 모양이에요. 왼쪽에는 폴더·대화 목록과 파일, 가운데에는 편집기, 오른쪽에는 Claude 터미널이 있어요. 터미널 아래에는 **한글이 깨지지 않는 입력창**이 있어요.
- AI 기능과 로그인·요금은 내 컴퓨터에 설치된 **Claude Code가 그대로 처리**해요. 이 앱은 API 키를 받지 않아요. 대화 내용을 컴퓨터 밖으로 보내지 않고, 분석·추적 기능도 없어요.

## 2. 준비물

| 준비물 | 확인 방법 |
| --- | --- |
| **Node.js 22 LTS** (앱을 직접 빌드할 때만 필요) | 터미널(Windows는 PowerShell)에서 `node -v`를 입력해요. `v22.`로 시작하면 돼요. 없으면 https://nodejs.org 에서 **LTS**를 설치해요. |
| **Claude Code CLI** | `claude --version`을 입력해 버전이 나오면 돼요. |
| **Claude 로그인** | `claude`를 한 번 실행해 안내에 따라 로그인해요. 앱 안의 터미널에서 해도 돼요. |

Claude Code 설치 명령(공식 안내: https://code.claude.com/docs/en/setup):

- **Windows (PowerShell)**: `irm https://claude.ai/install.ps1 | iex`
- **macOS (터미널)**: `curl -fsSL https://claude.ai/install.sh | bash`

> 앱을 처음 켜면 "시작하기 전에 확인해요" 화면이 Claude Code 설치 여부를 자동으로 확인해요. 없으면 **[🪄 자동으로 설치하기]** 버튼으로 위 공식 설치 명령을 앱 안에서 대신 실행해요. 설치가 끝나면 PATH와 상관없이 바로 쓸 수 있고, 다른 프로그램(안티그래비티 등)에서도 쓰고 싶으면 **[🔧 PATH에 등록하기]**를 누르면 돼요.

## 3. 처음 실행 (개발 모드)

이 폴더에서 터미널을 열고 차례로 입력해요.

```bash
npm install
npm run dev
```

- `npm install`이 끝나면 가상 터미널 부품(node-pty)이 자동으로 준비돼요. Windows·macOS는 미리 만든 파일을 쓰므로 따로 설치할 도구가 없어요.
- 앱 창이 뜨면 "시작하기 전에 확인해요" 화면부터 나와요.

그 밖의 명령:

| 명령 | 하는 일 |
| --- | --- |
| `npm run build` | 타입 검사 후 앱을 빌드해요 (`out/` 폴더). |
| `npm run typecheck` | 타입 검사만 해요. |
| `npm run test` | 자동 테스트를 실행해요. (실제 Claude Code는 실행하지 않아요) |

## 4. 설치 파일 만들기

```bash
npm run dist:win    # Windows 설치 파일 (.exe)
npm run dist:mac    # macOS 설치 파일 (.dmg) — 맥에서 실행해야 해요
```

- 결과 파일은 **`release/`** 폴더에 생겨요.
  - Windows: `release/PhilosophyClaudeWorkroom-Setup.exe`
  - macOS: `release/PhilosophyClaudeWorkroom-mac-arm64.dmg` (애플 실리콘), `PhilosophyClaudeWorkroom-mac-x64.dmg` (인텔)
- Windows 설치 파일은 Windows에서 만드는 것이 가장 쉬워요. (macOS·Linux에서 만들려면 Wine이 필요해요)

### 서명 없는 앱 실행 경고 넘기기

이 앱은 아직 코드 서명이 되어 있지 않아서, 처음 실행할 때 운영체제가 경고를 보여 줘요. 직접 만든 설치 파일이라면 아래처럼 실행하면 돼요.

**Windows ("Windows의 PC 보호" 파란 창이 뜰 때)**
1. 창 안의 **[추가 정보]** 글자를 눌러요.
2. 아래에 생긴 **[실행]** 버튼을 눌러요.
3. 설치 마법사에서 설치 위치를 고르고 [설치]를 눌러요.

**macOS ("확인되지 않은 개발자" 또는 "열 수 없음" 창이 뜰 때)**
1. dmg를 열고 앱을 **응용 프로그램** 폴더로 끌어 놓아요.
2. 응용 프로그램 폴더에서 앱을 **Control 키를 누른 채 클릭**(또는 오른쪽 클릭)하고 **[열기]**를 골라요.
3. 다시 뜨는 창에서 **[열기]**를 눌러요. 그래도 안 되면 **시스템 설정 → 개인정보 보호 및 보안**의 아래쪽에서 **[그래도 열기]**를 눌러요.

## 5. 사용 순서

1. **폴더 열기**: 처음 화면에서 **[📁 폴더 열기]**로 기존 폴더를 고르거나, **[➕ 새 작업 폴더 만들기]**로 이름만 써서 새 폴더를 만들어요. (기본 위치: `문서/필로소피 Claude 작업실` — 설정에서 바꿀 수 있어요)
2. **새 대화**: 오른쪽 클로드 패널의 **[＋ 새 대화]**를 눌러요. 대화 이름은 "새 대화 (11월 7일 오후 3:59)"처럼 자동으로 붙고, 바로 바꿀 수 있어요.
3. **작업**: 터미널 아래 **한글 입력창**에 할 일을 쓰고 **[보내기]**(Ctrl+Enter)를 눌러요. Claude가 파일을 고치려 하면 터미널에 확인 창이 떠요. 바뀐 파일에는 왼쪽 파일 목록에 **● 방금 바뀜**이 표시돼요.
4. **다음에 이어서**: 앱을 다시 켜면 마지막 폴더가 그대로 열려요. 처음 화면의 폴더 카드에서 **[▶ 이어서 작업하기]**를 누르면 그 폴더의 가장 최근 대화가 이어서 열려요.

알아 두면 좋은 기능

- 왼쪽 **📂 작업 폴더** 탭에서 대화를 누르면, 터미널을 띄우기 전에 **지난 대화를 말풍선으로** 볼 수 있어요. 위의 **[▶ 이 대화 이어서 하기]**로 바로 이어 가요.
- 대화 옆 **⋯** 메뉴: 이름 바꾸기, 메모, **목록에서 숨기기**, 갈라서 이어 하기(원래 대화는 그대로 두고 복사본에서 계속), Markdown으로 내보내기, 기록 파일 완전히 지우기(2단계 확인).
- **🔍 전체 검색**(Ctrl+Shift+F): 모든 폴더의 대화 제목·메모·내용에서 찾아요.
- **⚙️ 설정**: 클로드 패널 위치(오른쪽/아래), 밝은/어두운 테마, 화면·편집기·터미널 글자 크기, 자주 쓰는 문장, 다른 IDE(안티그래비티·VS Code) 실행 파일 위치.

## 6. 예전에 다른 곳에서 작업한 대화 불러오기

다른 IDE의 터미널에서 Claude Code로 작업했던 대화도 불러올 수 있어요.

- 처음 실행 화면의 **"3. 예전 작업 불러오기"**, 또는 처음 화면 위쪽의 **"앱 밖에서 Claude Code로 작업한 폴더 n개가 있어요 → [불러오기]"**를 눌러요.
- 폴더 목록에서 원하는 폴더에 체크하고 **[고른 폴더 목록에 추가]**를 누르면, 그 폴더의 대화가 모두 목록에 들어와요.
- 이미 등록한 폴더에서 앱 밖으로 새로 만든 대화는 자동으로 목록에 추가돼요. 바로 보이지 않으면 왼쪽 목록 위의 **[🔄 새로 고침]**을 눌러요.

> 이 앱이 저장하는 데이터는 Claude 기록의 "색인"일 뿐이에요. 진짜 대화 내용은 Claude Code가 `~/.claude/projects/` (Windows: `%USERPROFILE%\.claude\projects\`)에 저장한 기록이 원본이에요. 앱 데이터가 사라져도 위의 불러오기로 다시 만들 수 있어요.

앱 데이터 위치: Windows `%APPDATA%\필로소피 Claude 작업실\app-data.json`, macOS `~/Library/Application Support/필로소피 Claude 작업실/app-data.json`

## 7. 문제 해결

### "Claude를 찾을 수 없어요"
1. 터미널에서 `claude --version`이 되는지 확인해요. 안 되면 2번의 설치 명령으로 설치해요.
2. 설치했는데도 앱이 못 찾으면 **⚙️ 설정 → Claude Code → [고르기]**로 claude 실행 파일을 직접 골라요.
   - Windows 예: `C:\Users\내이름\.local\bin\claude.exe` 또는 `C:\Users\내이름\AppData\Roaming\npm\claude.cmd`
   - macOS 예: `/Users/내이름/.local/bin/claude` 또는 `/opt/homebrew/bin/claude`
3. 설치 직후라면 앱을 껐다 켜요.

### 안티그래비티(또는 VS Code) 터미널에서 설치하면 어떤 사람은 되고 어떤 사람은 PATH 오류가 나요
`'claude' 용어가 cmdlet, 함수, 스크립트 파일 또는 실행할 수 있는 프로그램 이름으로 인식되지 않습니다` 같은 오류예요. 사람마다 다른 이유는 다음과 같아요.

1. **설치 프로그램은 PATH를 고치지 않아요.** 공식 설치 명령은 claude를 `내 폴더\.local\bin`(macOS: `~/.local/bin`)에 넣고, PATH(명령을 찾는 폴더 목록)에 없으면 "not in your PATH"라는 안내만 보여 줘요. 그 폴더가 **원래 PATH에 들어 있던 컴퓨터**(다른 개발 도구가 미리 넣어 둔 경우 등)는 바로 되고, **없던 컴퓨터**는 오류가 나요.
2. **PATH를 고쳐도 IDE를 완전히 다시 켜야 해요.** 안티그래비티 안의 터미널은 안티그래비티가 *켜질 때* 받아 둔 PATH를 그대로 물려받아요. 터미널만 새로 열거나 창만 닫으면 적용되지 않고, 프로그램을 완전히 종료했다가 다시 켜야 해요. 그래서 "껐다 켠 사람은 되고 안 한 사람은 안 되는" 차이가 생겨요.
3. **npm으로 설치한 경우 실행 정책에 막혀요.** `npm install -g`로 설치하면 `claude.ps1`이 만들어지는데, 학교·회사 PC처럼 PowerShell 스크립트 실행이 막힌 컴퓨터에서는 "이 시스템에서 스크립트를 실행할 수 없으므로…" 오류가 나요.
4. **그 밖에:** 32비트 "Windows PowerShell (x86)"에서 설치하면 실패해요. 예전에 설치한 Claude 데스크톱 앱의 `Claude.exe`가 CLI 대신 실행되기도 해요. CMD에서 PowerShell 명령(`irm …`)을 넣어도 오류가 나요.

**이 앱은 이렇게 해결해요**
- **[🪄 자동으로 설치하기]**: 공식 설치 명령을 64비트 PowerShell로, 이번 한 번만 스크립트 실행을 허용해(`-ExecutionPolicy Bypass`) 실행해요. 학교·회사 PC의 정책을 바꾸지 않아요.
- **PATH에 기대지 않아요**: 공식 설치 위치(`.local\bin`)를 직접 찾고, Claude 데스크톱 앱의 `Claude.exe`는 건너뛰어요. npm 설치본은 `claude.ps1` 대신 `claude.cmd`를 써서 실행 정책에 걸리지 않아요.
- **앱을 다시 켤 필요가 없어요**: [다시 확인]을 누를 때마다 레지스트리(macOS는 로그인 셸)에서 최신 PATH를 다시 읽어요.
- **[🔧 PATH에 등록하기]**: 공식 문서와 같은 방법으로 사용자 PATH에 폴더를 추가해요(Windows는 관리자 권한 불필요, macOS는 `~/.zshrc`에 한 줄 추가). 그 뒤 **안티그래비티를 완전히 껐다 켜면** 거기서도 `claude`가 돼요.

### "이어서 하기가 안 돼요" (폴더를 옮겼을 때)
- Claude Code의 대화 기록은 **처음 대화를 시작한 폴더 위치에 묶여** 저장돼요. 그래서 이 앱은 항상 원래 폴더에서 이어서 해요.
- 폴더를 옮기거나 이름을 바꿨다면, 처음 화면의 카드에 "⚠️ 폴더를 찾을 수 없어요"가 떠요. **[📍 새 위치 지정]**으로 옮긴 폴더를 골라 주세요.
- 새 위치에서 이어서 하기가 계속 안 되면, 폴더를 원래 위치로 되돌리거나 그 폴더에서 **[＋ 새 대화]**로 새로 시작해요. (최근 Claude Code는 다른 폴더의 기록도 찾아 주지만, 옛 버전은 못 찾을 수 있어요)

### "한글이 깨져요" / 글자가 겹쳐 보여요
- 터미널에 직접 한글을 치지 말고 **터미널 아래 한글 입력창**에 써서 **[보내기]**를 눌러요.
- 입력창이 안 보이면 터미널 아래 **[⌨️ 한글 입력창 보이기]** 또는 **⚙️ 설정 → 입력 → 한글 입력창 보이기**를 켜요.
- 글자가 너무 작으면 **⚙️ 설정 → 글자 크기**에서 터미널 글자를 키워요.

### 그 밖에
- 터미널 기능을 불러오지 못했다는 안내가 뜨면 앱을 다시 설치해요. 직접 빌드했다면 `npm install`을 다시 실행해요.
- 앱 데이터 파일이 손상되면 앱이 자동으로 백업(`app-data.json.bak`)에서 복구하고 처음 화면에 안내를 띄워요.

## 개발자를 위한 메모

- 구조: Electron(메인/preload/렌더러) + React 19 + Tailwind CSS 4 + Monaco(로컬 번들) + xterm.js + node-pty.
- 렌더러는 `contextIsolation`·`sandbox`가 켜져 있고, preload가 노출한 타입 지정 IPC(`src/shared/ipc.ts`)만 쓸 수 있어요. 메인은 모든 요청을 zod(`src/shared/schemas.ts`)로 검사하고, 파일 접근은 등록된 작업 폴더 안으로 제한해요(`src/main/fs/pathGuard.ts`).
- 새 대화의 세션 ID는 앱이 `crypto.randomUUID()`로 정해 `claude --session-id <UUID> --name "<이름>"`으로 넘겨요(`src/main/claude/commandBuilder.ts`). 터미널 출력에서 ID를 긁어 오지 않아요.
- 대화 목록·기록은 공식 Agent SDK의 `listSessions()`·`getSessionMessages()`·`renameSession()`·`deleteSession()`만 사용해요(`query()`는 쓰지 않아요). 기록 파일을 직접 읽는 비상용 코드는 `src/main/claude/transcriptReader.ts` 한 곳에만 있어요.
- 테스트: `tests/main`(node 환경), `tests/renderer`(jsdom).
